# metrics/v1

## Purpose

`metrics/v1` defines the provider-neutral BaseHarbor contract for an application-provided metrics signal source.

The application declares the endpoint it provides. It does **not** request Prometheus, VictoriaMetrics, Mimir, Grafana or another collection/storage product.

## v1 semantics

- Direction: `provide`.
- Signal format: OpenMetrics-compatible text exposition over HTTP.
- Source identity: logical source name plus workload service.
- Source endpoint: workload service, target port and HTTP path.
- Default conventional path may be `/metrics`, but the path is explicit contract data.
- Provider placement, scrape interval, retention, storage topology and query endpoint are deployment/platform policy.

A source declaration is application intent because it describes an interface the application exposes. Collection policy is not application intent.

## Provider requirements

A conforming metrics provider must:

1. reject malformed or unreachable source definitions before claiming readiness;
2. collect only sources selected by platform policy;
3. preserve BaseHarbor application, environment, service and source attribution;
4. avoid manual target editing;
5. verify actual metric ingestion/scrape, not only provider process health;
6. isolate target configuration so one application cannot silently replace another application's source;
7. avoid provisioning unrelated visualization, log or trace products.

## Reference provider

BaseHarbor v0.4.8 uses Prometheus as the first shared Compose reference provider.

Prometheus is an implementation of `metrics/v1`, not part of the portable application identity. Future compatible providers can replace it without changing the application contract.

## Explicit non-goals

`metrics/v1` does not imply:

- Grafana;
- Loki;
- Tempo;
- alert routing;
- a particular retention period;
- Kubernetes/OpenShift ServiceMonitor resources;
- Prometheus-specific recording or alerting rules.
