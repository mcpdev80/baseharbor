# messaging.pubsub/v1

`messaging.pubsub/v1` describes publish/subscribe delivery semantics.

## Required semantics

- Stable logical pub/sub resource identity independent of broker topology.
- Application-scoped connection credentials and trust.
- READY requires subscribe -> publish -> receive verification.
- Provider-specific exchanges/topics/bindings remain provider state.
- CloudEvents is adopted where event-envelope semantics apply; AsyncAPI may describe application messaging APIs.
- Broker protocol and product identity remain separate from portable application intent.

## Reference provider

BaseHarbor's current reference implementation is RabbitMQ.
