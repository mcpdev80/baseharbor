# telemetry.otlp/v1

## Purpose

`telemetry.otlp/v1` defines the provider-neutral BaseHarbor contract for exporting application telemetry through the OpenTelemetry Protocol (OTLP).

The capability describes protocol semantics, not an observability product. An application never requests OpenTelemetry Collector, Prometheus, Loki, Tempo or Grafana by naming this capability.

## v1 semantics

- Direction: `export`.
- Transport: OTLP over HTTP/protobuf.
- Signals: one or more of `traces`, `metrics`, `logs`.
- BaseHarbor supplies the resolved endpoint to selected workloads through standard OpenTelemetry environment variables.
- BaseHarbor applies stable application/environment/workload resource identity.
- A managed provider or an external OTLP destination may satisfy the same capability.
- Provider placement and concrete endpoint addresses remain deployment state.

The application-facing environment uses the standard OpenTelemetry variables:

```text
OTEL_EXPORTER_OTLP_ENDPOINT
OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
OTEL_SERVICE_NAME
OTEL_RESOURCE_ATTRIBUTES
```

BaseHarbor does not require an application SDK. Any OpenTelemetry-compatible instrumentation that honors these variables can use the binding.

## Resource identity

BaseHarbor uses standard OpenTelemetry semantic attributes where they exist:

- `service.name` identifies the selected workload service.
- `service.namespace` identifies the BaseHarbor application.
- `deployment.environment.name` identifies the deployment environment.

BaseHarbor-specific attributes may supplement, but never replace, standard semantic conventions where BaseHarbor identity has no standard equivalent.

## Provider requirements

A conforming provider must:

1. reject unsupported protocol/direction/signal combinations before mutation;
2. provide an OTLP HTTP/protobuf endpoint or bind an existing external endpoint;
3. keep provider-specific topology and credentials outside portable application intent;
4. support idempotent binding;
5. verify a real OTLP export/receive path rather than only process health;
6. avoid provisioning unrelated observability products.

## Reference provider

BaseHarbor v0.4.7 uses OpenTelemetry Collector as the first managed Compose reference provider. The collector is shared and lazy: it is provisioned only when at least one application requests `telemetry.otlp/v1`.

An external endpoint can satisfy the same capability without BaseHarbor taking provider lifecycle ownership.

## Security

OTLP credentials, authorization headers, private keys and secret-bearing endpoint material must never enter the portable application contract or normal diagnostics. Deployment/runtime state may reference or inject security material at the trusted boundary.

## Explicit non-goals

This capability does not imply:

- Prometheus or metrics storage;
- Loki or log storage;
- Tempo/Jaeger or trace storage;
- Grafana or dashboards;
- alerting;
- a Kubernetes/OpenShift collector deployment;
- a complete observability stack.

Those are separate platform/provider concerns.
