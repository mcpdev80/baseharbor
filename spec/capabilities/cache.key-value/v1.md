# cache.key-value/v1

A provider implementing `cache.key-value/v1` supplies an application-owned logical Redis-compatible key/value resource.

## Required semantics

- Stable logical resource identity per application/name.
- Provider-specific instance/container/object identity remains deployment state.
- Application-scoped access credentials or credential references where authentication is supported.
- Redis-compatible application connectivity for the current v1 contract.
- Cross-application access denied by default.
- Preflight must complete before provisioning mutation.
- Provider verification requires a real authenticated protocol probe such as PING/PONG.
- A managed workload binding is READY only when the Redis-compatible endpoint, TLS trust material and credentials are projected through the canonical Service Binding workload boundary and pass structural verification.
- Compatibility projections such as `REDIS_URL`, `VALKEY_URL`, `REDIS_CA_FILE` and `VALKEY_CA_FILE` are not the canonical portable binding and MUST NOT be treated as proof that arbitrary application code consumed the capability.
- BaseHarbor readiness verifies BaseHarbor-managed provider, binding and workload convergence; it does not claim to introspect arbitrary in-process client behavior unless an application-specific semantic verification contract exists.
- Destructive lifecycle operations must respect provider scope and lifecycle ownership.

## Reference provider

BaseHarbor's current reference implementation is Valkey.
