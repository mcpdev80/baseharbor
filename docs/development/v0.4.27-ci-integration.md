# Isolated v0.4.27 CI implementation

Status: **draft implementation, disabled, not independently qualified**.
No workflow in this directory is registered with GitHub Actions. No changes to
v0.4.26 executors, release pins, settings, secrets or runners are required to
inspect and test this draft. Do not merge or install it during the release freeze.

## Implemented path

| Stage | Source and behavior |
| --- | --- |
| Submission | `deploy/ci/r27/r27-router.yml`: ready/open/`ci:validate` PR events; no synchronize listener. A develop push requests integration coverage. |
| Trusted dispatch | `scripts/r27-ci.py dispatch`: re-fetch PR head/base/merge SHA, require same repository, ready/open state and develop target; dispatch only the separately pinned `ci-policy/r27` executor source. |
| Planning | `r27_ci_plan.py`: read Git objects without candidate checkout; reuse `pr-diff-base.py`, `pr-gate-plan.py`, `pr-selected-runtime-matrix.py` and canonical `pre-release-resume.py:GitInputs`. Unknown impact, unsupported native gates and unconfigured checks block. |
| Execution | `r27-executor.yml`: fresh hosted jobs, exact synthetic PR integration or integration commit, read-only repository permission, no retained Git credentials, no signing/publishing secret. Candidate code never runs in the plan or issuer job. Atomic native execution reuses the existing reusable workflow. |
| Issuance | `r27-issuer.yml` and `r27_ci_issuer.py`: fixed-source checkout; independently fetch complete run/attempt/job inventory through the existing restricted authenticated transport; recompute policy and plan; require every expected job successful and unique; recheck current PR/base before signing. |
| Persistence | `r27-ci.py publish`: verify the public signature, recheck freshness and create one bounded receipt in `baseharbor-plan/evidence/r27/`; identical retry is idempotent, conflicting content or write denial blocks and retains the local signed file. |
| Offline verification | `r27-ci.py verify`: verify public Ed25519 signature, policy/source pins, expected commit and stage. No GitHub lookup, retained run, signing secret or enabled rollout is needed. |

The protected executor workflow's run name binds stage, PR number, candidate,
base, synthetic integration commit and artifact digest. The authenticated API run
must name that workflow and have the separately pinned executor SHA, exact run
ID/attempt and successful completed outcome. A run name alone is not authority.
PR merge parents and computed tree are independently checked by the existing
diff owner. Stale or foreign requests cannot borrow successful executor jobs.

## Policy and key custody

`deploy/ci/r27/policy.json` is a canonical proposed policy. The exact-byte SHA-256
must come from separately protected `R27_POLICY_DIGEST`, never a candidate value.
`R27_TRUSTED_EXECUTOR_SHA` must similarly identify independently reviewed source.
The protected executor branch must point at that commit. A changed branch pin,
policy or unrecognized source fails closed.

The proposed receipt uses Ed25519, with a 32-byte private seed available only to
the issuer step and a public key for offline verification. This deliberately
does not expose the legacy HMAC prototype's shared signing/verifying secret to a
planner or developer. The seed is removed from the process environment before
child processes run. Neither private key nor publish token enters candidate jobs.
The implementation uses `cryptography==50.0.2` and `PyYAML==6.0.3`; the legacy
HMAC/archive modules remain isolated compatibility prototypes, not trust anchors.

Independent source and policy review must happen before configuring the proposed
protected execution branch, issuer environment, public anchor, signing seed,
Planning-scoped publisher and rollout flag. None has been provisioned here.
The environment flag is an operational lock, not an authentication mechanism.

## Coverage and reuse limits

The adapter inherits the existing v0.4.26 gate inventory and validators without
editing that inventory. It adds a finite exact-path R27 preparation lane under
the independently pinned proposed policy. This does not qualify that policy or
accept the future release's new domain gates. Deletes, renames and unknown paths
stay under the conservative existing planner and block when unqualified.

`r27_commit_receipt.schedule` verifies prior public signatures and exact input
fingerprints, invalidates changed inputs and newer supplied negative outcomes,
and prevents release smoke reuse across a changed request/artifact. It is **not
yet connected to workflow scheduling**. Workflow execution currently reruns its
selected checks. Before automatic reuse, implement retained receipt discovery,
authenticated newer-negative ordering and independent final-check corroboration;
do not infer reuse from unsigned outputs or a past overall run conclusion.

The policy intentionally has no fabricated v0.4.27 Demo pin or smoke command.
Native requests require an accepted immutable Demo SHA; unsupported non-atomic
gates remain blocked. Release requests require an independently accepted
`release-smoke` executor, and its signed input includes both exact candidate and
artifact digest. A source build or `--version` is not that end-to-end proof.
The adapter supports such a protected binding, but no accepted artifact smoke
owner was available in the inspected source. Release execution therefore blocks.

## Before this can be called complete CI

1. Finish retained receipt scheduling and newer-negative handling without
   discarding successful checks from a partially failed run.
2. Independently qualify the proposed exact-path map, source pin and commands;
   bind all required access/authority/delivery/runtime domain gates and native
   fixture/consumer pins. Do not claim absent product tests are discovered.
3. Bind the real exact-artifact smoke executor and complete release catalog.
4. After v0.4.26 closeout, separately authorize installation and provision the
   protected branch/environment. Replace existing PR trigger routing as one
   reviewed change; do not activate both the old #1055 route and this router.
5. Qualify real label/ready/dispatch, stale head/base, wrong source, key isolation,
   selected native jobs, denied publication and idempotent retry on exact source.
   Bind the new final result to Required Checks only after that qualification.

Installing templates, editing repository settings, running native qualification,
merging, tagging and publishing a release are not part of this isolated change.

## Local verification

The focused R27 suite exercises the existing archive/receipt/origin modules and
the new pipeline using real temporary Git commits and synthetic merges, actual
Ed25519 signatures, the real restricted transport with only HTTP IO replaced,
offline CLI verification and create-only/idempotent publication negatives.
Workflow boundaries are inspected and all dormant YAML files are checked with
actionlint v1.7.12. These are deterministic checks, not independent review or
evidence of activated GitHub delivery.
