## Current evidence boundary

The current Session 2 integration adds a common application apply/up
acknowledgement path with concrete plan IDs, separate acknowledgements, stale
source/Target revalidation and typed machine error details. It retains pending
provider owners in the existing registry before materialization, preserves old
bindings until verified runtime retirement, and keeps previous deployment
intent across interrupted apply attempts. These are implementation increments,
not evidence that every mutation authority is covered.

Canonical application backend inventory now covers PostgreSQL, Valkey,
RabbitMQ and MongoDB services, including named instances and HA networks.
Selective native container retirement preserves sibling services and both
named and anonymous volumes. Changes within a retained provider, including
individual named service or management UI removal, enter the same impact
model. The native Docker and Quadlet removal adapters preserve their existing
ownership checks; retirement does not substitute destructive destroy.

Development Identity routing follows the selected realization. External OIDC
does not materialize a local Keycloak/login authority; application-scoped
Keycloak does not bootstrap a second shared operator realization. The
existing selected shared realization retains its supported operator path.

Actual consumer function/material/effect receipts, every remaining direct
mutation authority, all-family supported consumer reconfiguration and native
isolated Docker/rootless Podman gates still require integration/qualification.
No warning alone, preserved unused service or local adapter test closes them.

Local unit coverage includes data-preserving runtime retirement and canonical
Identity inventory/retirement/re-add files. This does not yet prove native
Identity usability, all providers or double acknowledgement integration.
Full Go tests and vet passed for the preceding local implementation; later
changes require their applicable checks. Docker/rootless Podman, exact-SHA
ecosystem compatibility and documentation/readiness acceptance remain pending.
No pre-release, merge, tag, release or production mutation is authorized.

The next runtime increment projects each existing application broker as an
ancillary realization in the same union and impact model. Removing one broker
requires its own acknowledged consequence even when another application keeps
the shared OpenBao provider available. Removing the last runtime-permission
consumer no longer depends on finding a released Secrets Capability binding.
The native control-plane adapter selects only the unneeded OpenBao/PostgreSQL
containers declared by the union and preserves volumes, networks, credentials
and recovery files. Broker recreation also removes only its selected container;
project-wide shutdown must not affect consolidated workloads or backends.

Runtime Explorer machine and interactive mutations now use one operation
authority. Ownership accepts only actually declared native services or
workloads, not arbitrary containers sharing an application project label.
This consolidation does not yet provide the required universal impact consent
or actual final/partial effect receipts for Explorer operations.

Protected certificate observations include the public certificate fingerprint
and actual start/expiry when present. Bundles use the common time window of all
certificates; current plans distinguish not-yet-valid, within-window and expired
material without binding the acknowledgement to a changing countdown. This is
time-bound evidence, not chain trust, revocation, future issuance/renewal or
continued authenticated access.
Local tests cover sharing, permission-root release without a Secrets binding,
retained native data, foreign ownership, interrupted removal/retry, and broker
inventory correspondence with its renderer. Native acceptance remains open.

External registration storage now rejects damaged, duplicated, trailing,
oversized, unprotected or redirected owner files without overwriting recovery
state. Writes use unique synchronized temporary files; final registration
removal can retry when its unbound registry projection was already released.
The integrated MCP and HTTP unregister paths call the same
`removeExternalProviderWithImpact` authority and carry typed provider-change
consent. The corresponding CLI uses that authority as well. Existing active
cross-Target references and external ownership constrain the concrete plan;
this source implementation does not establish actual external-service or
all-consumer continuity.

Selective Podman retirement also retires only the corresponding verified
container Quadlet definitions and reloads the user generator. Generated volume,
network, environment and sibling container definitions remain. Retrying after
definition removal still reloads an earlier stale generator cache. Tests reject
foreign/duplicated/replaced definition ownership and preserve sibling material;
fake systemctl evidence does not qualify actual boot or rootless runtime behavior.
