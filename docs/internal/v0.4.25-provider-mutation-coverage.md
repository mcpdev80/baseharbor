Working inventory for [#872](https://github.com/mcpdev80/baseharbor/issues/872)
and [PR #881](https://github.com/mcpdev80/baseharbor/pull/881).

deployment's aggregate impact scope before cleanup. Scope acknowledgements and
separate full-reset data consent cannot be replaced by `--yes` or leaf consent.
Protected publication changes invalidate consent. Default remote retirement
retains its publication/credentials/deployment owner for explicit reactivation.
Source tests cover these boundaries; actual full-reset and remote retirement /
reactivation journeys still require exact-candidate native acceptance.

The direct user clarification of 2026-10-11 10:58 Europe/Berlin supersedes
earlier permanent-veto wording: missing continuation is a concrete consequence
the developer can deliberately accept. Alternative-less or fully destructive
effects require **Achtung** and two explicit acknowledgements of the current
plan. Ordinary apply consent does not grant these acknowledgements or data
deletion. Unknown facts stay unknown; no successful handoff is invented.
Authorization and ownership remain necessary to operate on resources.
