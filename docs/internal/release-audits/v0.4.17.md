# v0.4.17 dependency and security release audit

Status: release-blocker decision record for issue #530.

This audit records the explicit v0.4.17 decision for every Renovate finding that can materially affect the release. A deferred item is not ignored: it has a reason, a follow-up boundary, or both.

## Decision matrix

| Finding | v0.4.17 decision | Rationale |
| --- | --- | --- |
| OpenBao 2.6.3 -> 2.7.0 | **ADOPT in #532 / PR #531** | BaseHarbor is pre-1.0 and has no production installation base requiring compatibility with unreleased internal storage layouts. The old `storage.file` implementation and the intermediate Raft design are therefore removed rather than migrated or dual-supported.

v0.4.17 uses OpenBao 2.7.0 with a dedicated database/user in the existing PostgreSQL control-plane provider, PostgreSQL `verify-full`, native OpenBao TLS, `tls_auto_reload`, and a hybrid-PQC-first TLS preference with classical fallback.

No legacy file-storage migration path exists. The current architecture is authoritative.

## Go support floor

v0.4.17 keeps:

```text
go 1.25.0
```

Neither `x/crypto` nor `x/sys` may silently raise that product support floor. A future Go >=1.26 move must update the declared module baseline, CI/toolchain images and support documentation as one intentional platform change.

## Provider image coverage

Renovate now includes a `custom.regex` manager for OCI image constants embedded in Go source in addition to the normal Go module, Dockerfile, Compose and GitHub Actions managers.

This prevents provider images encoded in runtime/provider code from being invisible to the dependency dashboard. Version changes remain human-reviewed for embedded provider images.

## Native-TLS relationship

The dependency audit and #529 are intentionally coupled only where necessary:

- OpenBao 2.7.0 uses dedicated PostgreSQL storage in the existing control-plane provider, native `tls_auto_reload`, and hybrid-PQC-first TLS; no legacy file-storage/Raft compatibility path remains.
- Keycloak, Prometheus, SeaweedFS S3 and OpenTelemetry Collector use their currently shipped versions' native TLS capabilities.
- Loki and Tempo keep the documented service-access adapters for v0.4.17 because removing them safely requires coordinated client-side/internal transport migration, not merely deleting a Caddy service.
- remaining Caddy usage is therefore an explicit realization decision, not an accidental default.
