# BaseHarbor v0.4.15.1 release audit

## Scope

v0.4.15.1 is the final v0.4.15 hotfix release and is tracked by #459.

Release-scoped fixes include the v0.4.15.1 hotfix children referenced by #459 and closed by PR #477, including #481 and #482. Deferred work remains outside this release, notably #480 (Docker/Podman log-collection convergence) and #483 (stable application/deployment/provider-instance identity, planned for v0.4.19).

## Architecture and engineering review

The hotfix preserves the existing v0.4 contracts:

- portable `baseharbor.yaml` application intent remains separate from Target/runtime configuration;
- shared providers remain Target/provider-owned, while applications own only their scopes/bindings;
- shared OpenBao recovery state persists only an operator-held file path reference under the Target;
- the shared OpenBao provider can automatically unseal from that Target-scoped reference when the recovery file is present;
- Docker and Podman continue to use the same semantic lifecycle contract;
- cross-application connectivity resolves the consolidated `bh-<target>-<application>-<environment>` project identity while retaining legacy project-name compatibility;
- Runtime Broker keeps the stable internal Compose service identity `broker` for reliable Docker syslog forwarding.

## Security review

- Recovery material remains outside normal BaseHarbor state; only its absolute path reference is persisted.
- Persisted recovery references fail closed when unavailable or invalid.
- Application destroy/rename does not remove the shared OpenBao provider or Target-level recovery reference.
- Existing ownership/fail-closed behavior for foreign resources remains unchanged.
