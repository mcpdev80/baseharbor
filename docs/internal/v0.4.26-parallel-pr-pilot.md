# v0.4.26 parallel PR pilot

This report qualifies the existing parallel-PR pilot evidence for core-901. It
uses existing GitHub pull requests and Actions runs only. No benchmark run,
runtime matrix or release matrix was started for this report.

All timestamps are UTC. "Runner minutes" below means the sum of observed
executed-job wall time from GitHub job logs, not rounded billing minutes.

The two product pull requests were genuinely independent in product scope and
were open at the same time, but their final regular CI runs did **not** execute

## Independence and shared integration

The final #934 diff against trusted develop base
`e8b021fe63c61abc0990a560e5f2915bb70c2c13` contains only the two new
`cmd/baha` files. The final #935 diff against integrated develop
`8820207463221384b1b9951d8ee335ba944554a1` contains only the two
`internal/repositoryinspect` files. The product changes do not share files and
neither overwrote the other.

The shared interface was CI coverage rather than product code. #935 initially
failed closed on [run
38872599405](https://github.com/mcpdev80/baseharbor/actions/runs/38872599405)
because `internal/repositoryinspect` impact had no accepted focused executor
mapping. That gap was handled separately by reviewed CI PRs:

| [#955](https://github.com/mcpdev80/baseharbor/pull/955) | `514f552104a68c8f98566666bf139895d844145f` | [38881495869](https://github.com/mcpdev80/baseharbor/actions/runs/38881495869) | Strict-update-safe trusted qualification: reviewed source plus permitted clean trusted-target merges; unreviewed follow-up changes remain rejected |

not conflicting parallel writes. #935 then normally merged current develop and
kept only its two product files in the final diff.

## Selected, executed, reused and unnecessary checks

### PR #934

Trusted planning selected the checks required by the two `cmd/baha` files.
[Run 38869216983](https://github.com/mcpdev80/baseharbor/actions/runs/38869216983)
executed and passed:

- trusted plan and workflow policy;
- `cli-guided-tests`;
- `source-contracts`;
- `cli-vet`;
- `cli-build`;
- focused Python verifier/planner checks;
- Demo pin verification;
- the original public-contracts integration owner;
- the always-running `PR Selected Checks` final verifier.

The public-contracts job executed the existing authoritative integration owner;
it was not replaced by a synthetic PASS. Native runtime selection, exact
candidate, consumer pins, runner-interface work, Targeted HA, release preflight
and the legacy broad `validate` job were not required and were skipped.

The older [38813614933](https://github.com/mcpdev80/baseharbor/actions/runs/38813614933)
exact-source pilot remains useful source evidence, but its unrelated legacy
`validate` job failed. It is not reported as a green overall workflow and was
not reused as final PR acceptance.

### PR #935

After #955/#953 were integrated, trusted planning selected exactly the five
inspect validations in
[run 38882179679](https://github.com/mcpdev80/baseharbor/actions/runs/38882179679):

- `inspect-gofmt`;
- `inspect-package-tests`;
- `inspect-vet`;
- `inspect-consumer-tests` for `cmd/baha Inspect|Reconcile`;
- `inspect-consumer-build`.

The run also executed trusted planning, workflow policy, focused Python checks
and the required final verifier. It did not require public contracts, candidate
construction, consumer pins, runner-interface validation, selected runtime
gates, Targeted HA, release preflight or the legacy broad `validate` job;
those paths were skipped.

Earlier exact-source [38815960883](https://github.com/mcpdev80/baseharbor/actions/runs/38815960883)
proved the product logic, but final acceptance used the regular trusted lane
after the permanent CI mapping was independently reviewed and integrated.

## Runtime and cost record

The two final product runs consumed **8.51 observed runner-minutes in total**
(5.40 + 3.11). Their wall-clock envelopes total 3.25 minutes because jobs
within each run executed concurrently. There is no cross-PR wall-clock saving
to claim from these two final runs because they were sequential.

For context only, core-888 records historical successful native job wall times,
not a like-for-like baseline:

| Historical evidence | Docker | Podman | Sum |
| --- | ---: | ---: | ---: |
| [37713017303](https://github.com/mcpdev80/baseharbor/actions/runs/37713017303) complete journey | 25.4 min | 26.1 min | 51.5 min |
| same run Guided | 4.3 min | 5.1 min | 9.4 min |
| same run Backup/Restore | 7.5 min | 10.8 min | 18.3 min |
| [38642797305](https://github.com/mcpdev80/baseharbor/actions/runs/38642797305) Identity | 4.0 min | 4.7 min | 8.7 min |

None of those native jobs was necessary for #934 or #935. Their omission is a
demonstrated reduction in executed scope, but it is **not** reported as saved
minutes because no same-input legacy counterfactual run was executed.

The repository is public and these jobs used standard GitHub-hosted runners.
GitHub currently documents standard GitHub-hosted runner compute as free for
public repositories:
<https://docs.github.com/en/actions/concepts/billing-and-usage>.
Therefore the measured Actions compute charge for these standard-runner jobs is
**$0** under the current policy. This report does not measure artifact/cache
storage, network transfer outside Actions, developer time or future policy
changes.

## Limits

- PR lifetime overlap is not job concurrency.
- Final #934 and #935 CI was sequential; no cross-PR CI speedup is claimed.
- Runner-minute figures are summed observed job durations from logs, not
  GitHub billing-rounded minutes.
- Historical native timings are context, not a statistically valid before/after
  benchmark and not a savings claim.
- Missing or failed evidence remains missing or failed. In particular,
  #934's early broad `validate` failure and #935's earlier fail-closed
  unresolved coverage are preserved as such.
- No full journey, runtime matrix, release matrix or synthetic benchmark was
  started for core-901.
