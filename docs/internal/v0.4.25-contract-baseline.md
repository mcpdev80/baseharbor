## Characterization and next API handoff

`internal/application/v0425_baseline_characterization_test.go` covers explicit
service combinations, repeated identity-preserving reads, byte-preserved
authoring, no inspection state writes, and zero backend capability projection
with an explicit workload. Existing capability/deployment tests characterize
shared reuse, external ownership and stable deployment identity.

No new resolver API or fixture handoff is published yet. After release
validation, Session 1 publishes a tested small pure API using existing registry
and deployment snapshots; Session 2 consumes that commit before runtime edits.
Required cases: automatic, explicit compatible, missing, incompatible,
ambiguous, shared/reused, foreign, external/BYO, running, stopped-but-owned and
unverifiable. HTTPS must not imply Identity; external SQL must not imply Core.

The footprint is read-only `baseharbor.footprint/v1`: existing/shared versus
incremental requirements, measured/estimated/unknown with source. No invented
numeric estimates, discovery writes, scheduler or second registry.

#777 portable profile import/export and Host Platform semantics remain contract
work for Session 1 after Gate 0, without implementing onboarding, OS adapters,
Console, TUI or Wizard. These specifications are not delivered by this inventory.
