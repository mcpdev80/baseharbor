# v0.4.10 release audit

## Scope

v0.4.10 publishes the security/runtime hardening completed after the immutable v0.4.9 release validation exposed real Docker/Compose defects.

## Security/runtime closeout

- [x] PostgreSQL and Valkey managed runtimes are non-root and hardened.
- [x] OpenBao runs directly as non-root without a root init container or `CAP_CHOWN`.
- [x] OpenBao uses an explicit writable config tmpfs with a read-only root filesystem.
- [x] SeaweedFS, OTLP Collector, Prometheus, Caddy, Loki and Alloy are covered by real provider acceptance.
- [x] Runtime Broker, Runtime Executor and Connectivity Relay use explicit non-root identities and hardened Compose settings.
- [x] BaseHarbor-owned runtime image supports arbitrary non-root UID execution for prepared writable state paths.
- [x] Loki/Alloy provider-internal traffic is separated from loopback-only host publishing.
- [x] No managed logs provider receives a Docker/Podman socket.
- [x] Effective process UID is checked in the live security fixture, not only Compose `Config.User`.

Observed Stage-12 effective UIDs:

- PostgreSQL: 70
- OpenBao: 100
- SeaweedFS: 1000
- Runtime Executor: 65532
- Runtime Broker: 65532

All observed managed containers in that fixture also had `privileged=false`, read-only root, `cap_drop=ALL` and `no-new-privileges`.
