# v0.4.15 Service Access / TLS Baseline Audit

Issue: #397

Status: implementation complete in the feature branch; final external demo evidence and the cross-issue recovery contributor remain tracked separately.

## Architecture invariants

- TLS is mandatory for BaseHarbor-managed network endpoints.
- Portable application intent does not contain provider products, CA products, certificate paths, private keys or authentication products.
- Service access resolves transport security, authentication, trust source and workload projection behind provider/runtime boundaries.
- Managed-local issuance uses the provider-neutral `serviceaccess.Issuer` contract with OpenBao PKI as the current reference issuer.
- BaseHarbor CLI does not own CA private keys or long-lived issuer state.
- Runtime identity and Runtime Provider Executor identities use the same OpenBao-backed issuer boundary rather than an in-process CA.
- BYOC, static external PKI and issuer-backed external PKI are distinct lifecycle ownership modes.
- Connection metadata may be projected through environment values; certificate/key contents are file bindings and never PEM-in-env.

## Implementation evidence

### Managed-local issuer

Current managed-local flow:

```text
serviceaccess policy
    -> provider-neutral Issuer
    -> OpenBao PKI engine
    -> issue / renew / revoke
    -> provider/runtime projection
```

The old runtime CA implementation that generated/signs a CA in Go and stored a CA private key in OpenBao KV is no longer used by the production runtime identity paths.

### Service transport

- Control-plane PostgreSQL: native PostgreSQL TLS and SCRAM host policy.
- Application PostgreSQL: native PostgreSQL TLS and generated native database credentials.
- Valkey: generated `requirepass` plus BaseHarbor TLS access gateway.
- OpenBao: BaseHarbor HTTPS access gateway; native OpenBao authentication remains authoritative.
- SeaweedFS/S3: HTTPS access gateway plus scoped native S3 credentials.
- Prometheus/Loki/Tempo/OTLP: HTTPS access gateway with environment-aware service authentication.
- Runtime Broker: native HTTPS, mTLS identity and application-scoped runtime token.
- Runtime Provider Executor: native HTTPS with required/verified client certificate; internal control network only.

The complete inventory is maintained in `docs/spec/service-access-inventory.md`.

### Environment policy

`serviceaccess.Resolve` enforces:

- dev: TLS mandatory, authentication may resolve to zero-ceremony trusted-local access;
- test/stage/prod/custom managed environments: authentication required;
- shared gateway state cannot silently downgrade from an authentication-required state back to anonymous dev access.

### Workload projection

The current compatibility projection includes:

```text
DATABASE_URL
DATABASE_CA_FILE
REDIS_URL / VALKEY_URL
REDIS_CA_FILE / VALKEY_CA_FILE
AWS_CA_BUNDLE
OTEL_EXPORTER_OTLP_CERTIFICATE
OTEL_EXPORTER_OTLP_CLIENT_CERTIFICATE
OTEL_EXPORTER_OTLP_CLIENT_KEY
TLS_CERT_FILE / TLS_KEY_FILE
BASEHARBOR_RUNTIME_*_FILE
```

The env value is a container-local path. The referenced CA/certificate/key is mounted as a protected/read-only file.

The external `baseharbor-demo` candidate branch `feat/v0415-managed-tls-bindings` consumes these paths through standard Go TLS configuration for PostgreSQL, Redis/Valkey, S3 and OTLP without BaseHarbor-specific SDK code.

### Host trust

Implemented managed-local trust lifecycle:

- `baha up` detects host trust after the managed issuer is ready;
- interactive installation requires explicit consent;
- `--yes` never implies host-trust modification;
- automation opts in explicitly through `--trust-host-ca` / `baha trust install --yes`;
- `baha trust export --output PATH` exports only public CA material;
- owned trust is recorded by fingerprint/backend/path;
- destroy verifies the currently installed certificate fingerprint before removing an owned anchor;
- external/BYOC trust roots are never claimed as BaseHarbor-owned;
- `baha down` preserves host trust.

### Renewal / rotation ownership

Machine-readable lifecycle state exposes only non-secret metadata:

- PKI source;
- lifecycle owner;
- renewal mode;
- issuer reference;
- server/client expiry;
- health/warning.

Managed-local and issuer-backed external PKI use `Issuer.Renew` during normal reconcile before expiry. BYOC/static external material remains operator-owned and is validated/warned through the same observation model.

`baha app status` and `baha app doctor` consume the same provider-neutral lifecycle observation.

### Recovery handoff

PKI/trust recovery is intentionally not implemented as a #397 CLI special case.

Issue #399 owns the recovery contributor and now explicitly requires:

- managed-local PKI/trust reconstruction metadata;
- regeneration of ephemeral identities/tokens;
- fresh explicit consent before reinstalling recovered host trust;
- BYOC/external ownership preservation without claiming external roots.
