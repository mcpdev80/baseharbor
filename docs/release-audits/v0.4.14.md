# BaseHarbor v0.4.14 release audit

## Scope

v0.4.14 completes the runtime-neutral reconciliation, security and lifecycle semantics planned in the roadmap before the v0.5 compatibility freeze.

Implemented scope:

- Desired/Observed/Diff/Ownership model in the shared core;
- typed missing/in-sync/drift/conflict/foreign-ownership/unsupported/degraded states;
- typed create/noop/repair/destroy/observe/blocked actions;
- provider-native observation before mutation;
- fail-closed ownership/conflict/unsupported/degraded handling;
- minimal repair and core-level no-op behavior;
- post-verification observation and convergence validation;
- Provider Integration Contract conformance coverage for the new semantics.

Explicitly not implemented:

- Kubernetes/OpenShift runtime behavior;
- Operator/CRD reconciliation;
- Argo CD/Flux/GitOps implementation;
- external provider process loading;
- v0.4.15 audit/evidence export semantics.

## Architecture review

The implementation adds one small runtime-neutral reconciliation domain below control surfaces. It does not introduce a second lifecycle engine.

The existing capability lifecycle remains authoritative:

```text
resolve -> preflight -> observe -> reconcile -> bind -> verify -> observe
```

Legacy provider drivers remain source-compatible. Typed reconciliation is additive through an optional observation interface.

Repository-inspection reconciliation remains separate: repository evidence compares detected code capabilities against portable application intent, while v0.4.14 reconciliation compares desired provider/runtime realization against observed state.

## Security review

Verified invariants:

- policy/preflight remains before mutation;
- foreign ownership blocks mutation;
- conflicting ownership blocks mutation;
- unsupported realization blocks mutation;
- degraded observed state blocks mutation rather than silently repairing unknown failure;
- externally owned resources are observe-only;
- BaseHarbor-owned stable state avoids unnecessary provider mutation;
- BaseHarbor-owned drift repairs only through the existing provider lifecycle;
- verification is followed by a second observation before successful convergence is accepted.

No secret-bearing provider fields were added to reconciliation results.

## Compatibility review

- Manifest v1 unchanged.
- Provider Integration Contract v1 unchanged.
- Existing provider drivers remain compatible.
- Compose remains the only complete runtime implementation.
- Runtime, capability and delivery provider axes remain independent.
- No Kubernetes/OpenShift-specific type enters portable application intent.

## Validation

Required before merge/release:

- targeted tests for `internal/reconciliation`, `internal/capability` and `internal/providerconformance`;
- full `go test ./...`;
- formatting/static repository checks used by the normal pre-release gate;
- final GitHub Actions release gate only after local/HF validation is green.

The targeted semantic test set is green on the v0.4.14 feature branch.
