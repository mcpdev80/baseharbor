# v0.4.8 release audit

This audit tracks the mandatory engineering and documentation gates for the Prometheus metrics platform integration.

## Architecture boundary

- [x] Application intent describes an application-provided `metrics/v1` source, never Prometheus.
- [x] OpenMetrics-compatible HTTP exposition is signal semantics; provider choice is separate.
- [x] Collection enablement is deployment/operator policy.
- [x] Prometheus is a replaceable Provider Integration Contract v1 reference implementation.
- [x] OTLP metrics export remains a separate `telemetry.otlp/v1` concern.

## Lifecycle and ownership

- [x] Preflight validates source semantics and policy before provider mutation.
- [x] Prometheus placement is resolved through the generic provider-placement model rather than metrics-specific scope policy.
- [x] Safe default shared Prometheus provisioning is idempotent; application-scoped placement is independently isolated.
- [x] Named shared boundaries create independent provider projects/state and do not widen access to unrelated applications.
- [x] Targets are generated automatically through protected BaseHarbor state.
- [x] Only declared/authorized metrics-source workload services join their application's isolated metrics network.
- [x] Application destroy removes only that application's target/trust-edge state or its dedicated provider, according to placement.
- [x] Shared provider lifetime is independent of one application's lifetime.
- [x] Registered/current placement is persisted and used for down/destroy cleanup instead of trusting transient override environment.
- [x] Placement migration converges/verifies the new path before removing the previous registered metrics placement.
- [x] Runtime-only `metrics/v1` permissions receive a protected provider-registry binding even without static `metrics.sources`.
- [x] Global destroy enumerates and removes all BaseHarbor-owned shared Prometheus default/sharing-boundary instances and data volumes.

## Isolation and security

- [x] Deterministic app/environment/service aliases prevent same-name workload service collisions.
- [x] Target files are application/environment scoped.
- [x] Unit coverage proves pruning one application does not remove another application's targets.
- [x] Prometheus receives no Docker/Podman socket.
- [x] Prometheus uses a read-only root filesystem, dropped capabilities and no-new-privileges.
- [x] Prometheus API is host-loopback-only.
- [x] Target state contains no credentials or secret values.
- [x] Metrics collection does not provision Grafana, Loki or Tempo.

## Verification

- [x] Unit tests cover manifest round-trip and fail-closed validation.
- [x] Provider contract conformance includes `metrics/v1`.
- [x] Runtime metadata does not claim a Prometheus binding when collection is disabled.
- [x] Workload networking tests cover source-service-only attachment.
- [x] Provider tests cover generated configuration, attribution and cross-application target pruning.
- [x] Placement tests cover safe defaults, explicit supported override, unsupported fail-closed behavior, named shared boundaries and registered-vs-desired placement separation.
