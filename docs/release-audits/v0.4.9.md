## Scope

v0.4.9 delivers provider-neutral centralized workload logs through Loki/Alloy and closes the hardening findings added after the v0.4.8 architecture/security review.

## Security review

Loki and Alloy are BaseHarbor-owned provider components with read-only roots, dropped capabilities, no-new-privileges and no Docker/Podman socket. Host-facing API/syslog listeners bind only to loopback.

Repository workloads are checked for privileged mode, container-runtime sockets, host network/PID/IPC namespaces, dangerous capabilities, devices and critical host bind mounts. Managed environments deny isolation bypasses before mutation. Development-only exceptions require explicit acknowledgement.

Provider state and registrations are owner-only. No secret value is written to Loki registration state, diagnostics or labels.

## Provider switch/core-coupling audit

A duplicated application-layer provider descriptor switch was removed; the application registry now consumes `capability.ReferenceIntegration` as the canonical descriptor mapping.

The remaining switches are intentional:

- capability -> reference provider resolution: authoritative reference-provider policy;
- provider -> default placement: authoritative deployment policy;
- provider placement -> runtime topology inside a concrete provider: provider implementation detail;
- named-resource provider instance IDs for SQL/KV: stable identity compatibility behavior.

No speculative global provider state machine was introduced.

## Compatibility

Manifest v1 remains unchanged. Logs are selected by platform/deployment policy and repository workload discovery rather than a Loki field in portable application intent.
