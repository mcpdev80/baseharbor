# BaseHarbor v0.4.1

BaseHarbor v0.4.1 adds the first reusable capability-provider domain core behind the existing v0.4 compatibility surface.

The release keeps Manifest v1 and the current Compose developer workflow intact while introducing typed capability, provider, logical resource and binding concepts plus a reusable machine-readable lifecycle model.

## Highlights

- **Capability/provider core:** portable capability requirements are resolved to explicit provider descriptors and logical resources.
- **Fail closed before mutation:** unsupported provider/capability combinations are rejected before lifecycle mutation.
- **Reusable lifecycle model:** plan, preflight, apply, bind and verify results are represented as structured data rather than terminal-only output.
- **Existing providers prove the model:** PostgreSQL, Valkey and OpenBao are represented through the shared capability domain without replacing the stable Compose implementation.
- **Machine-readable runtime bindings:** protected runtime metadata records logical capability/provider/workload relationships.

## Added

- Typed capability requirements and provider descriptors.
- Logical resource and workload binding types.
- Reusable lifecycle result, status and diagnostic types.
- Reference providers for PostgreSQL, Valkey and OpenBao.
- Protected capability binding metadata in the existing runtime contract.

## Changed

- Existing application capability types reuse the shared capability domain through compatibility aliases.
- Application planning resolves current capability/provider mappings before runtime mutation.
- The reusable lifecycle preflights every planned resource before any provider provisioning step is permitted.
- Current Compose provisioning and verification remain authoritative; v0.4.1 does not introduce a parallel runtime implementation.

## Security

- Unsupported capability/provider mappings fail before mutation.
- Provider negotiation never silently downgrades a requested capability.
- Shared capability results carry logical identities and diagnostics only; credentials, secret values and provider-specific protected configuration do not enter the portable domain model.

## Deprecated

No public command or Manifest v1 field is deprecated in v0.4.1.

## Removed

Nothing from the supported v0.4.0 CLI, Manifest v1 or Compose workflow is removed.

## Compatibility & upgrade notes

Existing v0.4.0 application repositories continue to use the same Manifest v1 and Compose workflow.

No application manifest migration is required.

v0.4.1 intentionally does **not** introduce:

- shared/dedicated/external provider registry semantics;
- provider ownership policy;
- a new public generic capability manifest;
- Kubernetes or OpenShift runtime implementations;
- cloud-specific provider implementations.

Those remain later v0.4.x roadmap work.

For the full technical history, see `CHANGELOG.md`.
