# BaseHarbor v0.4.26

## Create and change applications more easily

The interactive `baha app new` wizard helps you choose what your application
needs: SQL, cache, secrets, login or HTTPS. Review dependencies and estimated
resource use before starting. You can also create the project files without
starting services.

With `baha app edit`, change an existing application's needs and review the
effects before applying them. No returns to your selection; Cancel leaves an
unapplied change untouched. Applied changes are not automatically undone.
`baha app footprint show` displays estimated resource use in human-readable or
JSON output.

## Better automation

AI agents and other MCP clients can discover application editing and footprint
operations. Editing separates the proposed change from its approval and
execution, with the same ownership and safety checks as the CLI.

## More reliable backup and recovery

Application backups stop only the selected workloads. If stopping a workload is
interrupted, BaseHarbor attempts bounded recovery. PostgreSQL backup and restore
retain the database identity and protected TLS credentials. Shared services and retained data remain
subject to the existing ownership and consent rules.

## Compatibility

- Docker/Compose and native rootless Podman/Quadlet retain their support limits.
- Interactive New and Edit require a terminal; explicit creation arguments remain
  available for automation.
- `--yes` does not replace separate consent for destructive changes.
- This release adds no Console wizard, onboarding or new platform support.

See [Create and edit application needs](../how-to/application-needs.md) for a
walkthrough and [GitHub releases](https://github.com/mcpdev80/baseharbor/releases)
for downloads.
