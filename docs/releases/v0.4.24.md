# v0.4.24 — Draft release notes

**Status:** implementation in progress; not pre-release approved. All items below require final test evidence on the release candidate SHA before publication.

## Human CLI consolidation

- Task-oriented `baha new` entry point for application, development stack, local target, provider authoring and workspace creation.
- Direct root `baha init`, `inspect`, `list`, `backup` and `restore` commands reuse the existing domain lifecycle.
- Repository-aware `baha down` and `baha destroy` distinguish application actions from installation-level operations.
- Human help prioritizes common workflows, preserving operator namespaces.
- Unknown options for application stop fail with actionable typed usage errors.

## Core updates

- Added provider-neutral Core update planning with strict digest and ownership checks and explicit safe/backup/migration/unsupported classifications.
- Until provider-native SQL, Secrets and Identity upgrades have real runtime proof, binary self-update fails closed for existing Core installations instead of implying that provider reconciliation succeeded.
- `baha update --check` exposes the current Core reconciliation availability.

## Documentation

- New English and German human CLI workflow guides, linked from the corresponding Getting Started navigation.
- Core update contract describes required recovery, ownership, semantic verification, and cross-runtime evidence.

## Release blockers before approval

- Complete #610: remaining CLI/open, semantic parity, wizard and no-dead-end behavior.
- Complete #816: release-owned pinned provider manifests, lifecycle integration, backups, migrations, recovery, post-verification and Docker/Podman evidence.
- Complete #611: full CLI-driven documentation and GitHub Pages consolidation.
- Verify outstanding v0.4.23 carryover criteria, update all release/roadmap references and prepare changelog.
- Targeted source gates and runtime gates must be green at the exact candidate HEAD before full Pre-Release.

These notes are deliberately not a release-success declaration.
