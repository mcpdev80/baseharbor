# BaseHarbor v0.4.24 — Release notes (release candidate)

**Status:** release candidate; release not approved or published. The documentation describes implemented functionality separately from runtime acceptance.

## CLI and developer experience

- Task-oriented `baha new`, repository-aware application commands and guided operator workflows.
- Core/Target selection with `baha use`, Target-aware machine/JSON/MCP contracts and help/Doctor improvements.
- Application-managed SQL and cache operations are `baha app sql` and `baha app cache`. The older `app psql` and `app valkey` names are not documented as supported.
- Ownership-aware trust cleanup, including `baha trust uninstall --yes` and explicit preservation of foreign CAs.

## Core, providers and recovery

- Provider-update admission checks release-pinned digests, installation ownership, verified backup prerequisites and compatible provider versions.
- PostgreSQL physical basebackup, isolated safe extraction and file integrity verification are implemented. Native Docker and Podman rootless HA recovery transport acceptance passed at Core `49a2fab76079b98b5697ba9f556abb6e6c066cac`, [run 37954182113](https://github.com/mcpdev80/baseharbor/actions/runs/37945903026).
- An authenticated three-member etcd mTLS isolated snapshot/restore/boot/quorum path passed with a separate cluster identity while the source Patroni quorum remained healthy.
- SQL recovery receipts distinguish started/restored/recovered states and do not replay ambiguous commits automatically.
- OpenBao, Keycloak, SQL recovery and upgrade integrations have targeted tests; full live provider-state preservation and end-to-end rollback remain subject to acceptance.

## Console, Node Connector and Demo

- Console v0.4.24 integration work is tracked in [Console PR #4](https://github.com/mcpdev80/baseharbor-console/pull/4); source checks and production build passed on its package head. Final joint-Core live browser lifecycle/OIDC/RBAC acceptance is not yet established.
- Remote Target enrollment, mTLS sessions, runtime transport and Connector integration work is tracked in [Node Connector PR #5](https://github.com/mcpdev80/baseharbor-node-connector/pull/5); Go tests, vet and formatting passed on its package head. Final joint-Core Docker/Podman remote acceptance remains open.
- Demo integration must be pinned to the final immutable Core candidate and acceptance rerun on that exact pair. Older Demo evidence does not qualify this candidate.

## Evidence and support boundaries

- Core `67aec49d`: `go test -p 2 ./... -count=1`, `go vet -p 2 ./...`, CLI build and isolated Docker/Podman HA recovery gates passed, as documented in [Core PR #837](https://github.com/mcpdev80/baseharbor/pull/837).
- Native live DCS fence/activate/commit cutover and a coordinated physical SQL recovery were implemented and passed same-pin isolated rootless Docker/Podman runtime acceptance. Recovery explicitly rewinds post-backup transactions.
- Changed-image/provider-version qualification, plaintext-to-mTLS HA migration, complete OpenBao/Keycloak state preservation, and joint Console/Connector runtime acceptance remain **not release-qualified**. Ambiguous commit/fencing phases require reconciliation.
- PostgreSQL major-version upgrades, unsupported upgrade paths and unknown SQL-commit replays are not automatically admitted.
- No Pre-Release run, protected-branch merge, tag or published v0.4.24 release is claimed.

Release approval requires the remaining product acceptance gates and synchronized immutable Core/Demo/Console/Connector SHAs.
