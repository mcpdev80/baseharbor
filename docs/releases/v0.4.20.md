# BaseHarbor v0.4.20

Status: Work in progress

Release umbrella: #519

## Highlights

v0.4.20 makes repository adoption source-neutral and completes the safe Git workflow for developer workspaces before the v0.5 contract freeze.

### Adopt more existing repositories

BaseHarbor can inspect and adopt applications described with:

- Docker Compose;
- repository-authored Podman Quadlet;
- raw Kubernetes YAML.

The portable `baseharbor.yaml` describes logical workload components instead of carrying Compose-specific service or file identity.

This means the same application intent is no longer tied to the syntax used by the repository.

When a repository contains multiple plausible workload sources, BaseHarbor does not guess. Guided adoption asks which source is authoritative and records that repository choice separately from the portable application contract when necessary.

### Kubernetes repositories can be understood before Kubernetes runtime support

v0.4.20 can inspect and adopt raw Kubernetes manifests without requiring a live cluster.

This release does **not** add the Kubernetes Runtime Provider. A repository can therefore be understood and adopted even when the currently selected Runtime Provider cannot yet run that workload source. BaseHarbor reports that limitation explicitly instead of silently translating or changing the application.

### Safer multi-repository workspace updates

The existing multi-repository workspace gains:

```text
baha app workspace status
baha app workspace update --check
baha app workspace update
```

BaseHarbor uses the installed Git CLI and only performs safe fast-forward updates when the working tree is clean, an upstream exists and history has not diverged.

It does not automatically stash changes, reset worktrees, rebase, merge divergent branches, resolve conflicts or switch branches.

### Clearer repository inspection

`baha app inspect` now reports workload-source ambiguity and adoption results consistently across Compose, Quadlet and Kubernetes repositories.

The normal developer flow remains small:

```bash
baha app inspect .
baha app init
baha up
```

## Not included in v0.4.20

The following remain planned for later releases:

- Helm workload-source support;
- Kustomize workload-source support;
- Kubernetes Runtime Provider;
- OpenShift Runtime Provider;
- Argo CD / Flux or generic GitOps delivery.
