# BaseHarbor v0.4.28

CLI semantics and optional Perses observability integration.

## CLI command semantics

Audit and harmonize the complete human `baha` command model — Target defaults, lifecycle scope, help and shell completion — before the v0.4.29 platform (WSL2, macOS) work. v0.4.28 focuses on a consistent CLI before platform work.

## Optional Perses visualization surface

v0.4.28 replaces the earlier planned Grafana dashboard UI with an optional **Perses** integration. Perses is a provider-owned, dashboard-as-code visualization surface. It is not an application capability and is not part of the required Core bundle.

Perses is pinned at **v0.55.1** (image `persesdev/perses:v0.55.1`) for this release — the current stable release, selected for the critical security fixes introduced in v0.55.0 and the 2026-11-02 patch v0.55.1. This pin covers only the Perses provider component and is separate from BaseHarbor's own v0.4.28 release version. Authentication is opt-in; when enabled, an encryption key is mandatory — Perses refuses to start without a 32-byte key. The Prometheus, Loki and Tempo data backends are independent and remain available whether or not a visualization surface is selected.

> Perses is optional; its state may be `not_configured`, `configured_unverified` or `verified`. The normative state definition lives in docs/spec/management-access-v1.md.
