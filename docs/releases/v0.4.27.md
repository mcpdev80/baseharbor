# BaseHarbor v0.4.27

## One workflow, from laptop to remote infrastructure

BaseHarbor brings local application development and remote Core management together in one CLI-first workflow. Applications keep their portable requirements in the repository; the selected Target determines where and how they run.

The new workstation onboarding experience establishes trusted access to a Core on another machine without having to assemble TLS certificates and connection details by hand. A developer workstation connects to Core directly; the optional Node Connector is used for remote runtime hosts, not for workstation onboarding.

## Environments with sensible defaults

Deployment policies distinguish day-to-day development from test and production. Defaults protect stricter environments while allowing teams to review and deliberately override their own policies. Application requirements remain independent of the selected deployment environment.

## Safer, clearer application operations

Application registration, lifecycle locks and recovery are more resilient to concurrent commands and interrupted operations. Diagnostics distinguish unavailable, inaccessible and foreign resources more precisely, so an access problem does not look like an ownership conflict.

Existing application workflows continue through `baha init`, `baha plan`, `baha up`, `baha status` and `baha doctor`. Standard runtime and service interfaces remain usable without a BaseHarbor SDK.

## Docker, Podman and optional components

Local Docker/Compose and rootless Podman/Quadlet remain the primary runtime paths. The Demo illustrates adopting an ordinary application. Console provides an optional browser interface; Node Connector supplies controlled access to remote runtime hosts.

Core, Demo, Console and Connector are separately versioned and must use compatible integration builds. BaseHarbor does not replace an existing CI/CD system, registry or GitOps controller.
