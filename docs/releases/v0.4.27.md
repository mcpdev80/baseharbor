# BaseHarbor v0.4.27 — release preview

> **Draft, not published.** This describes the intended user-facing changes. The final release notes must be checked against the merged source, completed end-to-end tests and the published artifact versions before release.

## Easier setup across machines

The CLI-first workflow is being simplified for a machine running BaseHarbor Core and a separate developer workstation. The intended path is to start Core, onboard the workstation and import a trusted Target — without manually building TLS credentials or configuring connector components for the workstation-to-Core connection.

**Release check:** The new onboarding commands and their complete native end-to-end path are still under active review. Do not advertise this as shipped until those tests pass.

## Safer application operations

- Target deployment policies offer editable, best-practice defaults for development, test and production instead of treating every environment alike.
- Application registration and lifecycle operations have additional protection against competing operations, stale locks and duplicate application identities.
- Application listing and connection errors are more precise, making genuine access or recovery problems easier to diagnose.

## More predictable checks

CI changes reduce unrelated repeat checks and split selected Go test suites. This improves the contribution workflow; these are internal development improvements rather than new end-user features.

## Compatibility and availability

Docker and rootless Podman remain the current supported local runtimes. Console, Demo and Node Connector compatibility must be verified against the final Core commit; a source-code change or green unit test alone is not release qualification. Kubernetes and OpenShift support must not be inferred from this release.

No upgrade or migration action is claimed here until verified. For installation instructions and supported paths, consult the [documentation](https://mcpdev80.github.io/baseharbor/).
