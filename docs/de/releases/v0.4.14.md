# BasisHarbor v0.4.14

v0.4.14 schließt die gemeinsame Aussöhnung, Sicherheit und Lebenszyklus-Semantik ab, die vor dem Einfrieren der v0.5-Kompatibilität erforderlich ist.

Das Release implementiert keine Kubernetes oder OpenShift. Es definiert das laufzeitneutrale Abgleichverhalten, das aktuelle Compose-Provider und zukünftige Runtime/Delivery-Adapter wiederverwenden können.

## Hinzugefügt

- Gemeinsam `internal/reconciliation` Domain-Modell mit eingegeben Gewünscht, Beobachtet, Diff und Eigentümer Zustand.
- Ausgemusterte Aussöhnung heißt es:
  - `missing`
  - `in_sync`
  - `drift`
  - `conflict`
  - `foreign_ownership`
  - `unsupported`
  - `degraded`
- Getippte Aktionen:
  - `create`
  - `noop`
  - `repair`
  - `destroy`
  - `observe`
  - `blocked`
- Optionale anbieternative Beobachtung durch den bestehenden Fähigkeitslebenszyklus.
- Herstellerkonformitätsprüfungen für typisierte Abgleiche und geprüfte Konvergenz.

## Lebenszyklus-Semantik

Der gemeinsame Lebenszyklus folgt nun:

```text
intent
  -> resolve
  -> preflight
  -> observe
  -> diff + ownership decision
  -> mutation only when required
  -> bind
  -> verify
  -> observe again
  -> verified convergence
```

Bestehende Anbieter bleiben kompatibel. Anbieter, die die Abgleich-Beobachtungsschnittstelle implementieren, gewinnen typisierte Zustands- und Core-Level-Mutationsentscheidungen, ohne einen zweiten Lebenszyklus-Engine einzuführen.

## Sicherheit und Eigentum

- Konflikte, ununterstützte, degradierte und ausländische Eigentümerstaaten scheitern, bevor Anbietermutation geschlossen.
- Eine im Besitz von BaseHarbor befindliche fehlende Ressource löst `create`.
- Eine stabile Ressource im Besitz von BaseHarbor löst sich auf eine Kernebene `noop`; Anbietermutation wird übersprungen.
- BaseHarbor-eigene Drift löst sich auf `repair`.
- Externes Eigentum ist nur zu beobachten.
- Die Beobachtung nach der Überprüfung verhindert, dass ein Lebenszyklus Erfolg meldet, wenn der im Besitz von BaseHarbor befindliche Staat sich nicht tatsächlich konvergiert hat.
- Eigentum-sichere Zerstörung bleibt eine Kernanforderung; BaseHarbor darf keine ausländischen Ressourcen löschen.

## Vereinbarkeit

- Das Manifest v1 ist unverändert.
- Provider Integration Contract v1 bleibt die Anbietergrenze.
- Bestehende Anbieter, die noch keine eingegebene Beobachtung aufdecken, behalten ihr bisheriges Lebenszyklusverhalten.
- Es werden keine Kubernetes/OpenShift-Felder zu portablen Anwendungsabsichten hinzugefügt.
- Keine Argo CD, Flux oder andere produktspezifische Liefermechanismen werden Teil des Bewerbungsvertrages.
