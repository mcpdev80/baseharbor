# BaseHarbor v0.4.12

v0.4.12 macht BaseHarbor agent-native über eine kleine, versionierte Maschinenschnittstelle über die gleiche deterministische Anwendungs-/Laufzeitsemantik, die vom menschlichen CLI verwendet wird.

Die Veröffentlichung fügt absichtlich kein KI-Framework, Embedded-Modell, Remote-Agent-Plattform oder generische Befehlsausführung hinzu. Coding-Agenten erhalten BaseHarbor-Semantik, keine Umgehung um sie herum.

## Hinzugefügt

- Maschinenvertrag `v1` für die unterstützte inspect/plan/status/doctor-Ergebnisoberfläche.
- `baha agent describe ` und`baha agent describe -o json` für die Entdeckung von Semantikoperationen, Sicherheitsklassifizierungen, Leistungsspezifikationen und MCP-Metadaten.
- `baha mcp serve` als lokaler stdio Model Context Protocol Server.
- Offizielles Model Context Protocol Go SDK v1.8.0 mit MCP `2026-07-28` als aktuelles Protokoll Ziel und verhandelt `2025-11-25` Kompatibilität.
- Vier bewusst kleine schreibgeschützte MCP-Tools:
  - `baseharbor.inspect`
  - `baseharbor.plan`
  - `baseharbor.status`
  - `baseharbor.doctor`
- MCP-Tool-Annotationen beschreiben Read-only, destruktive und Open-World-Semantik.
- Stabile Maschinenfehlerkategorien und versionierte JSON-Fehlerhüllen für Automatisierungsausfälle.
- Generische MCP-Client-Akzeptierung, die Tool-Entdeckung und -Ausführung ohne ein BaseHarbor-spezifisches Client-Plugin unter Beweis stellt.
- Canonical Englisch/Deutsch Agent-Maschine-Schnittstelle Dokumentation.

## Verändert

- Status plus TLS-Beobachtung verwenden jetzt ein gemeinsames typisiertes Ergebnis, das direkt von CLI, TUI und MCP verbraucht wird.
- Die Doktorensammlung produziert nun ein gemeinsames typisiertes Ergebnis, das direkt von CLI, TUI und MCP verbraucht wird, anstatt TUI/MCP-Adapter für die Ausführung eines CLI JSON-Pfads zu benötigen und ihn zurückzulesen.
- Inspizieren, planen, Status und Arzt strukturierte Ergebnisse identifizieren Maschinenvertrag `v1`.
- Die begrenzt BaseHarbor `AGENTS.md` Im Abschnitt werden Codierungs-Agenten nun aufgefordert, strukturierte BaseHarbor-Schnittstellen und MCP anstelle von Shell/Docker/Compose-Bypasses zu bevorzugen.
- Normale Entwicklung zielt jetzt auf die langlebige `develop` Integrationsbranche.`main` bleibt die freigegebene Quellleitung und schreitet durch Freigabeförderung oder ein explizites Hotfix voran.
- Vorab-Release-Validierungs-Defaults zu und validiert Kandidaten enthalten in `develop`; Release-Tags bleiben erforderlich, um auf die Quelle in enthalten zeigen ` main`.

## Sicherheit

- MCP ist stdio-only in v0.4.12: Es wird kein Hörnetzwerk-Socket, Ferntransport oder Remote-Authentifizierungsoberfläche eingeführt.
- Der MCP-Katalog enthält keine generischen `exec`, Schale, Docker oder Compose primitiv.
- Alle initialen MCP-Operationen sind schreibgeschützt und als solche explizit kommentiert.
- Maschinenreaktionen bleiben geheim; Akzeptanz injiziert ein Markergeheimnis und überprüft, ob es nie in MCP-Antworten erscheint.
- Provider-globale Anmeldeinformationen, Laufzeit-Sockets und Provider/Runtime-Bypass-Pfade sind nicht Agenten ausgesetzt.
- Strukturierte Fehler liefern umsetzbare Maschinencodes, ohne dass geheime diagnostische Nutzlasten erforderlich sind.
- MCP-Tool-Annotationen werden als Entdeckungs-Metadaten behandelt, nicht als Sicherheits-Grenze; die Sicherheits-Grenze bleibt die explizit registrierten BaseHarbor semantischen Operationen.

## Veraltet

Nichts wird von BaseHarbor in v0.4.12 neu missachtet.

Die MCP-Implementierung hängt nicht von Protokollfunktionen ab, die von MCP deprecated sind.`2026-07-28` wie Roots, Sampling oder MCP Logging.

## Gelöscht

Nichts wird aus dem BaseHarbor-Anwendungsvertrag oder dem bestehenden menschlichen CLI-Workflow entfernt.

## Kompatibilität & Upgrade-Notizen

- Manifest v1 bleibt die portable Applikationskompatibilitätsoberfläche.
- Bestehende menschliche CLI-Befehle halten ihr normales Verhalten aufrecht.
- Bestehende JSON-Verbraucher sollten den Zusatzstoff auf höchster Ebene tolerieren `contract_version` Bereich.
- Agent/MCP-Verbraucher sollten BaseHarbor Maschinenvertrag behandeln `v1` und die MCP-Drahtprotokoll-Version als separate Versionsdomänen.
- `baha mcp serve` erfordert keine Daemon-Konfiguration und kommuniziert nur über stdin/stdout.
- Bestehende Anwendungen müssen keine agentenspezifischen Felder hinzufügen `baseharbor.yaml`.
- Kubernetes/OpenShift-Laufzeitverhalten, Remote-MCP-Transport/Auth, OIDC/RBAC/JIT und anwendungsbezogene MCP-Funktionen bleiben in der Zukunft bestehen.
