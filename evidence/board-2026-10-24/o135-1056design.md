## Exact implementation design (one correction worker)

One package, same three scripts, on the existing #1056 owner branch. No product source outside these three.

### 1) `scripts/pr-gate-plan.py` — kill the executable bootstrap fallback (F1)
- Lines **1165–1168** (and obsolete helper `bootstrap_eligible`, 746–794; remove it and its call entirely, plus any now-dead
  constants/`BOOTSTRAP_*` references). Replace the `or` fallback with strict-only:
  ```python
  # fail-closed: an unmatched/malformed/missing/unreviewed record stays UNRESOLVED.
  binding_checks = (trusted_binding_checks(diff, repository, context_repository, context_target_branch)
                    if not unresolved else None)
  if binding_checks:
      require(binding_checks)
      return {...coverage_status='resolved'... strict reason...}
  # drop through to unresolved handling — never emit CI_CHECKS for a non-trusted record
  ```
  Keep every other exact-source qualifier (CORE_752 paths 1147–1164, pins 1180–1184, registration 1185–1193, CORE_754 1194–1204,
  cmd/baha block 1205+). Do **not** replace with path-only admission or magic-message admission. Correct the stale docstring
  claim that the exception "can never qualify the two bootstrap PRs" — with the fallback removed the register stays authoritative.
  Preserve #1046/AppID qualification unchanged (separate constant + qualifier elsewhere; not in scope here).

### 2) `scripts/pr-check-runner.py` — tighten the pins validator (F2)
- Lines **139–140**: keep `PINNED_PINS_REPOSITORIES` as the *allowed* set but add a required **connector role** so the gate's
  `connector.repository` must equal the **Connector** pin (`'mcpdev80/baseharbor-node-connector'`), never Console.
- Lines **157–228** `validate_pins_data`:
  - connector slot (186–199): require `connector.get('repository') == PINNED_CONSUMER_CHAIN_REPOSITORIES['connector']`
    (`mcpdev80/baseharbor-node-connector`); reject Console/any other repo in that slot; and require the connector commit to equal
    the single joint `connector_commits` value (fail if divergent).
  - `console` block (196–199): now actually assert `console.get('repository') == 'mcpdev80/baseharbor-console'` and
    `pins_data_exact(console['commit'])`; drop the unused `console_repo`/`console_commit` locals that were never read.
  - ecosystem block (214–226): additionally require every ecosystem `commit` to equal the joint Connector commit
    (`connector_commits` singletons), and validate the **exact consumes DAG** — for each role's `consuming` edges, the referenced
    role's commit equals its ecosystem commit — via the existing canonical helper `scripts/ecosystem_release_pins.py:validate_ecosystem_graph`
    rather than another graph engine. Keep supporting older **gate-only** metadata (no `ecosystem` block) but validate its declared
    origins the same way (Connector role + 40-hex).
  - Defensive: check `isinstance(dict)` before every `.get()`/attribute deref (currently 187/192/197 deref on unvalidated `pin`/`connector`).
  - Remote source existence/ancestry/authenticated receipts remain the release resolver's job; do not claim the local syntax proves them.
  - Correct the stale docstring (161–167) that asserts the joint-Connector invariant is enforced — it is not, until this change.

## Necessity / sufficiency

**Correction is NECESSARY.** cmf12 already proved both findings against immutable H; `bootstrap_eligible` yields a false strict-proof
reason for an unreviewed production path (F1, pre-existing but not cured by Q), and `validate_pins_data` returns success on wrong
origin / Console-as-Connector / divergent joint commit / inconsistent DAG edge (F2, introduced by #1056). H's current `bootstrap_eligible`
returning None for actual H means Q only selects the strict path for H; it does not qualify the fallback for later unrelated changes.
A fail-closed qualification policy cannot ship a known false-positive bootstrap route and an incomplete pins validator.

**Correction is SUFFICIENT** to cure both findings *for these two defects*, provided it removes the executable bootstrap route, tightens
the connector role + joint-Connector commit + consumes DAG in `validate_pins_data`, and extends the two test classes with the negatives
above. It does **not** by itself complete the full #1056 activation sequence documented in cmf12 (frozen reviewed R′ -> new record-only
prerequisite binding actual `reviewed_head=R′` with freshly measured raw SHA-256 of all three scripts -> separate merge review ->
genuine current CI); the correction changes the three script blobs, so the old Q must NOT qualify it automatically. This design states
that prerequisite order but performs none of it.
