## PRUEFPUNKT 4 — Product side: transient-only classification without bare `temporary` word-match (CX P2 / q114/#1060)

**Finding: the bare word-match persists.** `bootstrap.go:57` still contains `strings.Contains(s, "temporary")`. The `isTransientError` classification (bootstrap.go:41–58) classifies a retryable error by substring-matching a list that includes the literal `"temporary"`. This is exactly the CX-P2 pattern: a naked word-match, not a real transient classification. In Go, `net.OpError` surfaces OS-level `ECONNREFUSED`/`ETIMEDOUT`, but Go's `net` package historically prefixes some errors with the word "temporary" (e.g. `temporary timeout`), so the match is only meaningful for a subset of OS errors and is a brittle proxy. It will also misfire on any unrelated error string containing "temporary".

**Verdict on this point: reported as OPEN.** This is precisely q114 / issue #1060 territory (transient-only classification implemented correctly in the planner, fail-closed, without a naked word-match). It **does not block #1052**: #1052's contract is "retry only positively-identified transient transport errors", and the retry ENABLE/DISABLE decision itself is correctly wired (permanent errors fail immediately via the classification gate). Fixing the classification granularity is a downstream follow-up owned by #1060, not a defect in the #1052 merge decision. I list it here as an open P2 finding per the mission's explicit instruction, and it does not change the verdict below.
