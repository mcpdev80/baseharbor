## Fix implementation

### bootstrap.go:41–59 — transient-only classifier

Removed the naked `strings.Contains(s, "temporary")` admission. Final classifier admits only positively-identified transport/listener failures:

```go
func isTransientError(err error) bool {
	if err == nil {
		return false
	}
	s := err.Error()
	return strings.Contains(s, "connection refused") ||
		strings.Contains(s, "connection reset") ||
		strings.Contains(s, "network unreachable") ||
		strings.Contains(s, "no such host") ||
		strings.Contains(s, "i/o timeout") ||
		strings.Contains(s, "operation timed out") ||
		strings.Contains(s, io.ErrUnexpectedEOF.Error()) ||
		strings.Contains(s, "reset by peer")
}
```

`temporary` (line 57) is the sole removal. The doc comment is corrected: it no longer claims "temporary" admission. Permanent TLS/CA, permission, and missing-executable failures never match and fail fast. The retry loop at bootstrap.go:157–162 keeps its `!isTransientError` fail-fast gate, the `memberRestartAttempts=5` cap, and the `ctx.Done()` backoff. Ownership/secret handling elsewhere unchanged.

## Regression strengthening (bootstrap_test.go)

Retained the five existing cases. Added:

- **Negative classifier cases** (`TestIsTransientErrorRejectsIncidentalTemporary`, `TestIsTransientErrorRejectsMixedPermanentTransport`): a permanent TLS error carrying the word "temporary" in its message and a mixed permanent/transport diagnostic must be classified non-transient. These fail if the product re-introduces any bare-word admission.
- **Exactly one retry-enabled attempt + zero writes for permanent failure** (`TestUnsealFailsImmediatelyOnPermanentNonTransientError`): `permErrorExecutor` now records a per-member `preUnsealAttempts` counter and returns the permanent TLS error (`x509: certificate ... temporary failure in name resolution`) — a message that contains the incidental word "temporary" yet must not be retried. Assert `preUnsealAttempts == 1` (exactly one attempt, no retry), `writes == 0`, `retryAttempts == 0`, and `errAttempts == 1` (single probe execution). Omitting permanent classification makes `preUnsealAttempts` climb and fail the exact-1 bound.
- **never-answers counts real per-member submissions + zero writes + final transport cause** (`TestUnsealFailsFastWhenMemberNeverAnswers`): `neverAnswersExecutor` now records per-member `execAttempts` and `writes`; `ExecProjectInput` no longer swallows — it records a submission and returns a transport error. Assert `execAttempts == 5` (exactly five real pre-unseal probes), `writes == 0`, and the returned error wraps the final transport cause (no retry-after-final, no swallowed error).
- **exact per-member phases for all 3 members** (`TestUnsealConvergesAfterMemberRestartRace`): each member asserts exactly one write (`writes == 1`), exactly one successful post-unseal verification (`postUnsealVerification == 1`), `verifiedAfterUnseal` true, a real initial Inspect (`inspectCount == 1`), and pre-unseal attempts matching the transient window (`preUnsealAttempts == transientWindow[member]`). No member exceeds five executions. Omitting a per-member write or post-verification breaks the exact-1 bound.
- **transient post-unseal verification failure path** (`TestUnsealFailsOnTransientPostUnsealVerification`): a member answers pre-unseal, gets unsealed (one write), then the post-unseal verification probe fails with a permanent TLS error → unseal fails fast with the wrapped permanent cause, `writes == 1`, `postUnsealVerification == 1`. Exercises the post-unseal `probeMemberState(..., true)` retry path with a non-transient failure.
- **invalid JSON callCount == 1** (`TestProbeMemberStateInvalidJSONNoRetry`): `invalidJSONExecutor` now records per-member `execAttempts`; assert `execAttempts == 1` (first-attempt/no-retry for non-transient invalid JSON). Omitting the immediate-return path lets a retry-then-same-error implementation pass; the exact-1 bound fails it.

All counters are per-member (`haMemberState` fields), keyed by `service`/`targetMember`, so the three members never consume each other's scripted transitions.
