## OPS-4 IMPLEMENTATION

### Problem

Evidence-Dateien im baseharbor-plan Repo duerfen KEINE Markdown-Checkboxen enthalten
(CarBoard-Regel). Kopier-Skripte/Prompts muessen `- [ ]` und `- [x]` zu Unicode
maskierten Varianten transformieren (z.B. `- [\u2610 ]`, `- [\u2611]`) bevor die
Inhalte im Plan-Repo landen.

### Lösung

`evidence/board-2026-10-22/scripts/sanitize_evidence_for_plan.sh`:
- Liest STDIN oder Datei-Argument
- Ersetzt `- [ ]` -> `- [ ]` (leere Box: U+2610 BALLOT BOX)
- Ersetzt `- [x]` / `- [X]` / `- [done]` -> `- [\u2714]` (checked: U+2714 CHECK MARK)
- Ersetzt `- [-]` / `- [>]` -> `- [\u25CB]` (other markers)
- Output bleibt sonst unveraendert (kein Content-Change, nur Checkbox-Maskierung)
- Exit 0 bei Erfolg, 1 bei Syntaxfehlern

### Doku-Zeile im RUNBOOK

RUNBOOK wird um einen Verweis auf sanitize_evidence_for_plan.sh erweitert:
"Bevor evidence/... nach baseharbor-plan kopiert wird, durch pipe nach
sanitize_evidence_for_plan.sh | bash, um CardBoard-Checkboxen zu maskieren."

## OPS-5 IMPLEMENTATION

### Problem

Wenn AgentGateway-Modell-Latenz >5s: KEINE neuen Spawns dieses Modells.
Laufende Lanes behalten oder auf anderes Modell umsiedeln.

### Lösung

`basics-check.py` LATENCY-Flag (neue Funktion `gateway_latency()`):
- curl --connect-timeout 5 --max-time 10 `http://192.168.6.132:4000/v1/models`
- Misst `time_total` pro Modell-Endpunkt
- Cache 60s (Datei: `basics-check-latency.json`)
- Flag >5s: "LATENCY: model {name} gateway latency {X}s (>5s) - NO NEW SPAWNS of this model"
- Flag <2s cleared: "LATENCY: {name} recovered ({X}s <2s) - spawns allowed"
- Read-only: kein Spawn, kein Kill, nur Flag
- In Pool-Count-Check einflussen: wenn LATENCY-Flag aktiv, flagged auch "POOL: {model} below target due to LATENCY hold"
