## 1. The 3 q53 hypotheses

From `q53-podmanlocal.md` (lines 120-124), the cleanup-preparation path runs
`failure-runtime-diagnostics.sh cleanup-preparation --unpause-owned`, and the only
podman-specific behaviors it can exercise are:

1. **Quadlet auto-collection** (script line ~166): the Quadlet monitor daemon
   auto-collects exited/dead containers; the script accounts them (`accounted`,
   not an error). Podman-only.
2. **`env -u XDG_CONFIG_HOME -u XDG_DATA_HOME podman ps`** (acceptance.sh
   `runtime_cmd()`, lines 60-66): drops fixture isolation for the native
   container lookup. Podman-specific — Docker reads its own socket regardless
   of XDG vars.
3. **Paused-container state** (script line ~172): `--unpause-owned` calls
   `podman unpause <ID>` on owned containers whose inspected `State.Paused` is
   true. Both runtimes support paused state; `unpause` is the distinguishing call.

## 2. The authoritative error

`scope-result.json` from run **39986732724** (podman, release branch at
`25c3196`-adjacent `a0ff20e`), downloaded via `gh run download`:

```json
{
  "target": "demo-podman",
  "runtime": "podman",
  "mode": "--unpause-owned",
  "outcome": "failure",
  "accounted": [],
  "errors": [
    "owned runtime evidence unavailable: TimeoutExpired"
  ]
}
```

`accounted: []` rules out (1): nothing was auto-collected — the failure is not an
accounted/recovered container. The error is a `TimeoutExpired` raised inside
`owned_containers()` before any `unpause` ran — the inventory itself never
returned. That is the podman daemon's **socket-activation cold-start stall on the
first native `podman ps`**, not a paused-state or XDG-isolation logic fault.

## 3. Cross-check against the 3 hypotheses

- **(1) Quadlet auto-collection** — **No.** `accounted: []`; the guard would have
  appended an `accounted` entry for any auto-collected container. The error is a
  hard `TimeoutExpired`, not an accounted recovery. (This was the class behind the
  earlier `o54`/`o56` `preparation=1` *accounting* failures; those are resolved by
  the #118 port. The *current* podman failure is a different, timing class.)
- **(2) `env -u XDG_*` isolation** — **No.** The XDG drop is intentional and
  correct for the host-context podman lookup; it does not raise `TimeoutExpired`
  and does not leave `accounted: []` with a present-but-unverified container.
- **(3) Paused-state / `unpause`** — **No.** `--unpause-owned` never runs: the
  error is raised in the inventory (`owned_containers`), before the inspect loop
  that unpauses. A paused/unpause fault would surface as
  `owned paused container could not resume`, not `TimeoutExpired`.

The decisive contrast is docker-vs-podman timing in the **same run 39986732724**:

| Job | cleanup begin | outcome | duration |
|-----|---------------|---------|----------|
| docker | 16:46:26 | `cleanup: complete` (PASS) | ~57 s |
| podman | 16:48:17 | `TimeoutExpired` at 16:48:37 | **20.0 s, failed** |

Docker's daemon is always warm; its inventory returns fast. Podman's rootless
daemon is socket-activated and, on a cold runner after the ~20 min acceptance
run, stalls on its first native call for ≥ 20 s — exactly the per-call ceiling
that raises `TimeoutExpired`.

## 4. The single location to fix

`baseharbor-demo/scripts/failure-runtime-diagnostics.sh`, the `run()` helper's
timeout budget (lines 47-57):

- The per-call ceiling `limit=20` and the shared `deadline = start + 60` were
  calibrated for a warm docker daemon. On podman's first cold `ps` they are
  too small.
- **Fix (o56b, commit `25c3196` on `work/v0.4.26-ecosystem-release`):** widen the
  podman budget only — `call_limit = 60` for podman vs `20` for docker and
  `deadline = start + 90` for podman vs `60` for docker. A genuinely hung call
  still times out within the extended budget, so the safety guarantee (a real
  `TimeoutExpired` is still a real failure) is preserved.
- Accounting semantics are untouched: 20 unit tests and the o23
  `debug-cleanup-provenance-order` regression both pass.

This is the one workflow/script change required to clear the current podman
`preparation=1` `TimeoutExpired`. Verified: run **39990941852** (branch
`work/v0.4.26-ecosystem-release` at `25c3196`) — both jobs `success`. The
downloaded `scope-result.json` now reads:

```json
{ "target": "demo-podman", "runtime": "podman", "mode": "--unpause-owned",
  "outcome": "success", "accounted": [], "errors": [] }
```

The #118 accounting-port (earlier `o56`) and this budget fix are two independent
layers: the port fixes *what* is accounted; this fix makes the podman inventory
reachable at all.
