# BaseHarbor v0.4.2 release audit

## Scope

Issue #157: shared, application-scoped and external provider registry.

Implemented:

- typed provider scope and ownership;
- persistent registry/discovery;
- shared-provider reuse;
- dedicated provider isolation;
- external provider bindings without lifecycle ownership;
- explicit update/backup/destroy provider-lifecycle decisions;
- current PostgreSQL/Valkey/OpenBao mapping;
- automatic adoption after successful apply/up;
- registry release after successful application destroy.

## Development-rules review

The implementation keeps provider placement outside portable application intent, uses explicit typed models, adds no dependency or generic plugin framework, serializes global state updates, persists atomically with owner-only permissions, rejects corrupt or ambiguous state, and preserves existing Compose provisioning.

## Documentation review

README, changelog, provider model, roadmap, release/versioning guidance and maintained German provider documentation are part of the v0.4.2 audit. Historical release documents and ADR version references remain historical.

## Compatibility

Manifest v1 and the existing Compose developer workflow remain unchanged. Existing v0.4.1 applications require no manual migration and are adopted on the next successful apply/up.

## Release message

The release notes explain user impact, rationale, safety, compatibility and intentionally deferred work rather than reproducing commit history.

## Validation

The release requires one consolidated PR validation on the final implementation/documentation head. CI must not be rerun speculatively.
