## OpenBao 2.7 architecture correction

The initial #530 audit captured the then-current `storage.file` implementation. #532 intentionally replaces that unreleased internal architecture instead of preserving it.

The final v0.4.17 runtime is:

- OpenBao 2.7.0;
- dedicated `openbao` database and least-privilege login in the existing PostgreSQL control-plane provider;
- PostgreSQL `verify-full` with explicit CA trust;
- native OpenBao TLS with `tls_auto_reload`;
- hybrid-PQC-first TLS preference with classical fallback;
- no `storage.file`, no intermediate Raft lifecycle, and no migration/dual-support path for unreleased 0.4.x state.

Bootstrap and PKI rotation are validated against that final architecture.

## Accepted update: go-oidc 3.21.0

v0.4.17 adopts `github.com/coreos/go-oidc/v3 v3.21.0`.

Required focused validation before final pre-release:

- discovery and issuer validation;
- JWKS parsing/refresh;
- ID-token signature/claim validation;
- managed Keycloak reference provider;
- operator OIDC path;
- negative issuer/signature cases.

## Renovate coverage

Normal managers already cover Go modules, GitHub Actions, Dockerfiles and Compose files.

BaseHarbor also embeds shipped provider/runtime image references in Go source. `renovate.json` now includes a regex custom manager for registry-qualified Go image constants, so Keycloak, Valkey, SeaweedFS, pgAdmin, Redis Commander, Prometheus, Loki, Tempo, OpenTelemetry Collector, Caddy while still required, and other matching provider images remain visible to Renovate.

The custom manager is review-only: discovering an image update never implies automatic provider/runtime adoption.

## Release rule

The final v0.4.17 pre-release runs only after:

1. #517, #526, #527, #528 and #529 focused validation is green;
2. go-oidc 3.21.0 focused identity validation is green;
3. static/source validation is green;
4. release documentation reflects the accepted/deferred decisions.

Deferred findings are deliberate release decisions, not ignored dashboard items.
