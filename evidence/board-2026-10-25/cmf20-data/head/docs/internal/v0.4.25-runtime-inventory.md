## Current standalone increment — 2026-10-12

The preceding baseline/initial implementation descriptions are historical.
The current provider inventory and remaining acceptance are maintained in
[v0.4.25 mutation coverage](v0.4.25-provider-mutation-coverage.md).
Prometheus/Loki now have canonical read-only inventory and data-preserving
selected-container retirement. The shared application consequence authority
uses these and the existing SeaweedFS/Collector/Tempo inventories. App-scoped
observability stop selects its module containers rather than stopping a
consolidated project. Retained material stays at its actual owner locations;
volume existence does not prove content, transient delivery or continuity.
Core/Target-wide enforcement, full consumer reconfiguration and final ecosystem
acceptance remain incomplete. This increment does not establish readiness.

Tempo shutdown qualification uses the upstream query-frontend shutdown fix in
[Tempo 3.1.0](https://github.com/grafana/tempo/releases/tag/v3.1.0)
([upstream correction](https://github.com/grafana/tempo/pull/7986)). Both local
and S3 configurations explicitly keep `storage.trace.block.version: vParquet4`;
this change does not opt existing owners into the new default write format.
Read-only retirement recognizes the exact previously generated 3.0.2 Compose
definition as well as the current definition, without rewriting it. Arbitrary
images, modified definitions and unprotected owner files remain rejected.
This is not proof of a live 3.0.2-to-3.1.0 upgrade: that transition, HA acceptance
and the final ecosystem candidate still need their own qualification.

Core inventory now uses the existing canonical protected-owner checks for UID,
hardlinks and parent links as well as the exact renderer shape. Provider impact
revalidation also binds protected file content internally, so equal size and
restored timestamps cannot conceal changed credentials/configuration. Secret
contents and credential-file digests are not emitted by this revision check.
These checks strengthen ownership and stale-plan detection; they do not replace
the still-required Core/Target mutation integration and actual consumer checks.

The retained, registered Tempo binding now projects a previous canonical image
or an unverified actual image as an `update` in the existing consequence plan.
An interrupted apply cannot become a no-op merely because its new Compose
definition was already written: actual Tempo-role image identities are read
and bound internally to the current plan revision. Resume/add operations also
display their materialization version and preserved block-write format. The
selected provider comes from the existing Target binding, not another resolver.
Runtime-only unbound owner/consumer reconciliation and full lifecycle coverage
remain mandatory unfinished work; no live-upgrade acceptance is implied here.
