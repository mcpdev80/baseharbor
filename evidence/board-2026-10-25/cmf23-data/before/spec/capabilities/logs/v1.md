# logs/v1

`logs/v1` describes runtime-neutral application log collection intent.

## Required semantics

- Log source identity uses stable application/component identity, never container names or runtime-native resource names.
- Runtime-native collection mechanisms remain below the provider/runtime boundary.
- Normal application intent does not select a log-storage product.
- Readiness/evidence distinguishes collection from backend persistence/query verification.
- Kubernetes pod/container logs, Docker/Podman streams and external log platforms can map to the same semantic source identity.

## Reference provider

BaseHarbor's current managed log backend is Loki; runtime log collection remains provider/runtime-neutral.
