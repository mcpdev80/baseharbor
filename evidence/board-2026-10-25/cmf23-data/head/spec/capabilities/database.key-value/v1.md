# database.key-value/v1

`database.key-value/v1` describes durable application-owned key/value data. It is distinct from `cache.key-value/v1`: loss of this state is data loss, not cache eviction.

## Required semantics

- Stable logical resource identity independent of provider/runtime object names.
- Durable persistence is enabled and positively verified.
- Application-scoped least-privilege credentials or credential references.
- Standard application-facing connection material through the Service Binding boundary.
- Successful readiness requires an authenticated write/read verification.
- Backup/recovery support is explicit; unsupported recovery must remain visible in evidence.
- Destroy and reconciliation preserve ownership boundaries for application, shared and external placement.
- Provider-specific persistence knobs, topology and storage implementation remain deployment/provider state.

## Reference provider

BaseHarbor's current reference implementation is Valkey with durable persistence. RESP compatibility is a provider/protocol property, not the portable service identity.
