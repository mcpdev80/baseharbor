# exposure.http/v1

A provider implementing `exposure.http/v1` makes one explicitly requested logical workload endpoint reachable through HTTP or HTTPS outside its normal workload-local boundary.

Endpoint discovery and exposure are separate concepts. Discovering or observing an application-owned HTTP/HTTPS publisher does not transfer lifecycle ownership to BaseHarbor.

## Portable intent

The application may declare only application-facing requirements:

- a stable logical exposure name;
- the selected logical workload service;
- the application target port;
- external transport requirement: `http` or `https`;
- visibility: `public` or `internal`.

The following are deployment/provider state and are not portable application intent:

- concrete FQDN;
- host-published port;
- container/pod name;
- Compose project/network names;
- certificate source path;
- reverse-proxy product or configuration;
- Kubernetes/OpenShift/cloud routing objects.

Omitted visibility is canonically interpreted as `public`.

## Required semantics

- Stable logical resource identity per application/exposure name.
- Stable logical target identity through the selected workload service; generated runtime container names are never application-facing identity.
- All provider preflight checks complete before provider mutation.
- Provisioning is idempotent.
- Failed new or changed provider realization rolls back BaseHarbor-owned traffic resources without deleting application-owned workload state.
- Destroy/release removes only BaseHarbor-owned exposure-provider resources.
- `public` realization is reachable through a host-facing provider binding; `internal` realization is restricted to local/internal provider reachability.
- Successful verification performs a real end-to-end HTTP/HTTPS request through the realized exposure.
- HTTP redirects are considered reachable.
- HTTP 5xx responses and unreachable endpoints are NOT READY.
- Normal status/diagnostics expose endpoint/exposure metadata and readiness, never provider secrets or private-key material.

## TLS boundary

HTTPS is one transport mode of the same `exposure.http/v1` capability; it is not a separate provider lifecycle.

The current Compose reference provider supports HTTPS with the existing/BYOC deployment TLS state. Certificate source paths and normalized key material remain deployment/provider state.

Managed ACME, OpenBao PKI issuance, automatic renewal/rotation and a broader portable certificate capability are outside this specification revision.

## Reference provider

BaseHarbor's current Compose reference implementation is Caddy.

Caddy is an implementation choice behind the Provider Integration Contract. A later Traefik, Kubernetes Gateway API, OpenShift Route or cloud provider can implement the same `exposure.http/v1` application intent without changing the portable contract.
