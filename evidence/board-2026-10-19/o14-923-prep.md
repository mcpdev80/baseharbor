## 2. Journeys the new two-stage MCP provider edit adds (per #998 real interfaces, read-only)

From `cmd/baha/app_registration_921.go` (#998 head, read-only in `worktrees/core-921-central-cli-mcp-registration` @ `a66e5de6`):

- **One tool, two phases:** `baseharbor.app.edit` (`machineMCPTool(... false)` = non-confirmable). Input `appMCPEditInput` (`:95`): `target` (required, exact resolved Target), `name`/`environment` (optional), `phase` (`"propose"`/`"apply"`, required), `desired` (required, `target` sub-required), `proposal`/`consent` (optional at schema, required for apply). **Snake_case JSON + `jsonschema` tags** — the #998 P1-A fix (was PascalCase/infer-required).
- **Phase-conditional boundary:** `propose` accepts only Target-bound `desired` intent, returns a typed `proposal` (`appMachinePropose`, `app_machine_adapters.go:280`). `apply` **requires both exact `proposal` and fresh `consent`** (`:136`), re-hydrates (`appMachineHydrate:112`), reconciles the decision (`appEditDesiredFromDecision`), and reaches `appMachineChangeDesired` (`app_machine_adapters.go:376`). This is the same accepted CLI edit authority reused, not a new lifecycle.
- **Typed negatives on the public boundary:** wrong Target → `machine.ErrorConflict` (`:115`); propose carrying proposal/consent → `validation_failed` (`:126`); apply without proposal/consent → `validation_failed` (`:137`); invalid phase → `validation_failed` (`:172`). All real `*machine.Error` (the #998 P1-B typed-owner fix; `ErrorConflict` is the pre-existing contract code at `internal/machine/contract.go:48`).
- **Journeys added vs. today:** (a) **machine discoverable + routable** via central registry (previously the interactive CLI/`console`-only path); (b) **typed two-phase consent over MCP** for machine clients with `code`/`cause`/`next`; (c) **exact-sHA immutable candidate** qualified through the real `baha` entry point; (d) **CLI/JSON/MCP parity** — CLI stays interactive (`runAppEdit`), JSON via `baha app edit -o json`, MCP via the two-phase tool.
- **What it does NOT add:** no new lifecycle, no new resolver, no new domain/state authority (release note: "One flow, two existing authorities"; capability intent → Application Contract; explicit provider preference → existing Target binding owner).
