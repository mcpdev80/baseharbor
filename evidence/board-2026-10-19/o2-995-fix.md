## Scope / what each fix does

1. Fixture manifest capability contract (no parser change, no exception):
   `cmd/baha/app_backup_restore_integration_test.go` swaps the legacy
   `postgres`/`redis` service keys for the shipped v1 capability grammar
   `sql`/`cache` and keeps `secrets`. The default SQL instance (postgres) and
   `secrets` capability match the downstream `metadata.PostgresResources[0]=="default"`
   assertion. An in-fixture `application.ParseYAML(manifest)` guard now fails the
   native acceptance test if the capability keys ever revert.
2. Non-native regression (no runtime started):
   `cmd/baha/app_backup_restore_integration_test.go` adds
   `TestBackupFixtureManifestMatchesCapabilityContract` (parses the real
   manifest and asserts identity + capability intent) and
   `TestBackupFixtureManifestRejectsLegacyCapabilityKeys` (asserts the shipped
   parser still rejects the legacy `postgres`/`redis` keys).
3. Bounded, redacted diagnostic for the owned cleanup path:
   new `cmd/baha/native_fixture_cleanup_diagnostics.go` builds
   `nativeFixtureCleanupDiagnostic(err)` with exactly three coarse,
   non-material fields — `caller`, `owner`, `classification` — derived from the
   `machine.Error` and the destroy scope owner subject. No hostname, path,
   revision, plan digest, deployment ID or guarded inventory material.
   `approvedNativeFixtureCleanup` (`cmd/baha/native_fixture_cleanup_test.go`) runs
   `destroyInstallation` into a buffer and, only on a guard refusal, emits the
   diagnostic via `t.Logf` (`[native-cleanup-diagnostic] caller= owner= classification=`).
   Ownership/consent guards are unchanged; only the discarded structured report
   is surfaced in a bounded, redacted form.
