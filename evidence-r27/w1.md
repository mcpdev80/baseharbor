## 3. How the execution proof works (not a filename match)

`pr-check-runner.py execute --check receipt-execution-tests`:
1. Runs `python3 -m unittest discover -s scripts -p "test_receipt*.py" -v` with `PYTHONPATH=scripts` and the repo as cwd — the same invocation the selected CI lane uses.
2. Requires return code 0 and a verbose line matching `(test_receipt_writer\.|test_receipt_verifier\.|test_receipt_chain\.|test_receipt_tasklink\.|test_ci_workflow_policy_receipts\.)` — i.e. at least one receipt suite actually executed.
3. Returns the exact executed suite list; a stubbed empty run raises `RuntimeError('...did not run')`.

This makes the CI result depend on actual receipt-suite execution and failure propagation, not on a planner path that merely resolves.

## 4. Shadow consumption after approval publication (F6)

The new `receipt-shadow.yml` is a reusable `workflow_call` job. It:
- Checks out the verifier from the authenticated trusted base (`pull_request.base.sha`, `persist-credentials:false`).
- Clones `mcpdev80/baseharbor-plan` `main` with `fetch-depth: 0` (full protected history, no shallow fetch).
- Runs `receipt_verifier.py retained` with the **exact** published `--receipt`, `--plan` (approved plan revision SHA) and `--candidate` (approved candidate SHA) passed as `workflow_call` inputs. No PR head, no live fallback, no GitHub API call after approval (`retained` is offline).
- Keeps a never-true job guard (`github.repository == 'mcpdev80/receipt-shadow-dormant'`) so nothing runs until a later cutover PR replaces it, arms the trigger from the approved approval job, and passes the published references. Existing triggers and required checks are unchanged.
