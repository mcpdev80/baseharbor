## Scope

Release-scoped work:

No Kubernetes/OpenShift runtime implementation, managed identity delivery, v0.5 contract freeze or unrelated provider expansion belongs in this release.

## Recovery architecture review

The application recovery unit is typed and ownership-aware.

Current recovery classes:

```text
application.metadata
database.sql
secrets
object-storage.s3
workload.storage
observability.logs
observability.metrics
observability.traces
security.pki
```

Supported application-owned state includes application metadata, managed SQL, the application-owned OpenBao secret scope, managed S3 contents, BaseHarbor-owned repository workload named volumes, selectable application log history and reconstruction of application/runtime identity state.

Application log history is selectable and not part of the default backup. Metrics and trace history remain explicitly unsupported until a safe application-scoped restore path exists.

External named volumes, bind mounts and external data stores remain outside BaseHarbor ownership and are represented explicitly as external/excluded contributors.

Portable recovery identity uses logical application resources. Physical Docker/Podman volume names remain deployment realization detail.

## PKI/trust review

The managed-local CA belongs to the Target-wide OpenBao issuer, not to one application.

Application recovery therefore does not copy the Target-wide OpenBao storage volume or CA private key into an application archive. Application/runtime leaf identities and trust edges are reconstructed from desired state after restore.

This avoids cross-application disclosure and preserves the existing Target/application ownership boundary.

## Audit/evidence architecture review

The v1 evidence bundle is a read-only projection of existing semantic models:

- desired state from Plan;
- enforced state from Policy;
- observed state from Status;
- verified result from Doctor;
- recovery contributor evidence from protected backup/recovery metadata;
- explicit exceptions and unsupported controls;
- bounded lifecycle audit events.

CLI JSON and MCP use the same collector. No second control plane, generic shell interface, provider-native escape hatch or vendor-specific SIEM backend is introduced.

Meaningful completed lifecycle operations are audited rather than every internal reconciliation step.

## Security review

- Evidence and audit records exclude secret values, tokens, access keys, private keys, credential-bearing URLs, prompt contents and model/agent reasoning.
- Audit state is Target-local, owner-only and bounded.
- Evidence bundles are deterministically ordered and carry SHA-256 tamper evidence.
- The digest is not represented as a digital signature, remote attestation or compliance certification.
- Recovery fails closed on ambiguous ownership and does not silently copy external state.
- Durable unsupported application-owned state must be explicitly excluded rather than silently omitted.

## Compatibility review

Manifest v1 remains unchanged.

Existing encrypted archives continue through the legacy recovery-manifest fallback. v0.4.16 archives carry typed recovery contributor metadata.

Docker Compose and Podman/Quadlet share the same logical recovery semantics. Provider/runtime physical resource names remain outside portable application intent.

## Post-acceptance hardening review

Real-world repository acceptance after the initial release-note preparation found and fixed additional lifecycle/adoption defects without expanding the portable Manifest v1 contract:

- #495 / #499 — deterministic init fails closed when repository workload intent is unresolved;
- #497 / #498 — effective rendered Compose configuration drift participates in convergence and READY state;
- #496 / #503 — managed SQL/cache consumer bindings use the Service Binding 1.1 workload boundary and are verified independently from provider health;
- #487 / #504 — incomplete/failed deployment state remains addressable and recoverable instead of becoming an invisible deployment;
- #501 / #506 — secondary SQL/cache references to replaced repository services are rewired only when semantically unambiguous and otherwise fail closed;
- #502 / #505 — destroy reclaims only ownership-proven named volumes exclusively belonging to replaced repository database/cache services.

The v0.4.15.1 fixed host-port fallback from #470 remains a mandatory regression requirement for this candidate. Current focused Source & Quality coverage includes the fixed-port tests together with the later repository-adoption fixes; no source Compose rewrite is introduced.
