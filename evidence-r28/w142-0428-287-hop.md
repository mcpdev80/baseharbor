## Root cause

Card commit `78e572f36` added an early incomplete-inventory fallback in
`cmd/baha/application_destroy_authorization.go`:

```go
if reset {
    if _, runtimeErr := application.ExistingRuntimeFiles(resolved.Store, resolved.Manifest); errors.Is(runtimeErr, application.ErrRuntimeNotApplied) {
        return buildIncompleteInventoryDestructionPlan(resolved, record, operation)
    }
}
```

This gate returned to the incomplete-inventory recovery **whenever runtime
files were absent, regardless of the deployment's observed convergence state**.
The incomplete path never reaches the stale-impact-consent recheck
(`current.Scope.PlanID != p.Scope.PlanID` → `stale-impact-consent`).

- Clean deployed records (`Observed.Ready == true`) whose runtime is only
  temporarily absent were misrouted to the incomplete inventory, producing a
  child plan with no scoped union (`Providers.Target == ""`) → CLI-2 "crossed
  Target boundary".
- Completed installs whose sibling scope changed (earlier sibling removed)
  reused a stale parent acknowledgement via the incomplete path → CLI-3
  "silently reused old parent acknowledgement".

Proven by instrumented probes: on the merge head, `second` (Ready=true, no
materialized runtime) routed `IncompleteInventory=true`; with the fix it routes
`IncompleteInventory=false` (complete path) and the stale guard returns
`stale-impact-consent` as the test expects.

## Fix

Gate the incomplete-inventory recovery on a genuinely stuck apply — an
unfinished-apply observation (state recorded, not ready) with never-materialized
runtime — via a new `isStuckUnmaterializedApply` helper:

```go
func isStuckUnmaterializedApply(resolved resolvedApplication, record deployment.DeploymentRecord) bool {
    if record.Observed.State == "" || record.Observed.Ready {
        return false
    }
    rtFiles := application.RuntimeFilesFor(resolved.Store, resolved.Manifest)
    _, composeErr := os.Stat(rtFiles.Compose)
    _, envErr := os.Stat(rtFiles.Env)
    return errors.Is(composeErr, os.ErrNotExist) || errors.Is(envErr, os.ErrNotExist)
}
```

This keeps card regression `TestW287DestroyAfterFailedApplyReturnsZero` /
`TestW287DestroyFailedApplyIdempotent` green: their failed-apply records are
observed unready (`Ready=false`), so they still route to the incomplete
recovery.
